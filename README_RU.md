# KSIVA AWARDS — PHP + PostgreSQL для Render

Это перенос серверной части на PHP 8.3; существующие `public/index.html` и `public/admin.html` оставлены без редизайна. База приложения и PHP-сессии хранятся в PostgreSQL, поэтому данные не зависят от временной файловой системы Render.

## Развёртывание на Render
1. Создай PostgreSQL в Render и скопируй **Internal Database URL** (если база и Web Service в одном регионе).
2. Создай Web Service из GitHub-репозитория, выбери **Docker** как Runtime.
3. В Environment добавь:
   - `DATABASE_URL` — Internal Database URL PostgreSQL;
   - `SESSION_SECRET` — длинная случайная строка (32+ случайных символа; PHP-сессии хранятся в PostgreSQL);
   - `ADMIN_PASSWORD` — новый пароль админки;
   - `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_CALLBACK_URL=https://ТВОЙ-ДОМЕН/auth/google/callback` — если нужен вход Google;
   - `JURY_EMAILS` — email жюри через запятую, если используется режим жюри;
   - `DISCORD_WEBHOOK_URL` — если используются объявления в Discord.
4. Deploy. При первом запуске PHP создаст таблицы PostgreSQL и стандартный список номинаций/подарков.
5. **Импорт старой SQLite-базы** делай только один раз: при первом деплое файл `migration/ksiva.sqlite` включён для переноса. После запуска сервиса открой Render Shell и выполни:
   `php /var/www/html/migration/import_sqlite.php`
   Если Shell недоступен, можно временно добавить в Dockerfile отдельную команду импорта, но сначала проверь, что новая база пустая. Импорт использует `ON CONFLICT DO NOTHING`, повторный запуск не перезапишет существующие строки.
6. После проверки удали `migration/ksiva.sqlite` из репозитория и сделай deploy. Не удаляй старый Render-сервис, пока не проверены регистрация, вход админа, голосование, чат и сохранение после повторного деплоя.

## Важно
- SQLite-файл, приложенный к исходному архиву, содержит 3 номинанта и 1 голос, но **не содержит аккаунтов пользователей**. Это не доказывает, что в живом сервисе аккаунтов нет — это лишь содержимое локального файла из архива.
- Импорт переносит доступные данные, но сессии из `sessions.sqlite` не переносятся; пользователям нужно будет войти заново после перехода.
- Изменяй переменные окружения только в Render Dashboard, не добавляй секреты в код/GitHub.
- Убедись, что `ADMIN_PASSWORD` задан. Не полагайся на старый хеш админа, если хочешь сменить пароль.
